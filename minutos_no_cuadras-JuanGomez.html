Enunciado formal

Problema 4.9: Minutos, no cuadras.

La pregunta en una oración

«¿Cuál es la ruta de menor tiempo en minutos desde la Terminal Norte hasta el Hospital General, y por qué difiere de la ruta con menos cuadras?»

En el transporte y la logística urbana, el trazo corto en pantalla engaña. Un tramo de avenida central que conecta dos puntos casi en línea recta puede estar saturado por semáforos, obras o congestión vehicular pesada, tardando más de media hora.

Por el contrario, un circuito de corredores secundarios y pasajes con preferencia de paso suma más cuadras físicas, pero se recorre en una fracción del tiempo.

BFS (Amplitud)

Trata todas las aristas con peso 1. Cuenta únicamente número de cuadras (saltos). Encuentra la ruta con menos esquinas, pero es ciega al tiempo real.

Dijkstra (Tiempo)

Suma los pesos reales positivos (tiempo en minutos). Examina la red expandiendo el vértice con menor tiempo acumulado, garantizando la ruta verdaderamente más rápida.

Mecánica interna

La cola de BFS vs. La cola de prioridad de Dijkstra.

BFS: Menos cuadras

Utiliza una cola FIFO (primero en entrar, primero en salir):

  1. Encola el origen A con distancia 0 cuadras.
  2. Saca el frente u y examina sus vecinos no vistos.
  3. A cada nuevo vecino le asigna dist[v] = dist[u] + 1.
  4. Al llegar al destino G, garantiza el menor número de saltos.

Resultado esperado: Llega a G por A → B → G en solo 2 cuadras.

Dijkstra: Menos minutos

Mantiene una cola de prioridad (pendientes) ordenada por tiempo acumulado:

  1. Fija dist[A] = 0 min y el resto en ∞.
  2. Extrae el pendiente u con menor tiempo acumulado y lo confirma.
  3. Relajación: Si dist[u] + tiempo(u,v) < dist[v], actualiza la marca de v.
  4. Se detiene al confirmar el destino G.

Resultado esperado: Confirma A → C → D → E → G en 14 minutos (4 cuadras).

    Respuesta y contraste

    Las dos respuestas frente a frente.

    ¿Por qué difieren? Porque BFS asume que cada cuadra cuesta 1 unidad abstracta, cayendo en la trampa de la Avenida Central. Dijkstra evalúa el costo real en minutos y descubre el rodeo rápido.

    Ruta Dijkstra (Óptima en tiempo)

    Tiempo total: 14 minutos
    Distancia en cuadras: 4 cuadras

    Ruta: Terminal Norte (A) → Calle Comercio (C) → Plaza Mayor (D) → Bulevar (E) → Hospital General (G).

    Usa 4 cuadras fluidas (3 + 4 + 3 + 4 = 14 min). ¡Ahorra 20 minutos de espera!

    Ruta BFS (Menos cuadras)

    Tiempo total: 34 minutos
    Distancia en cuadras: 2 cuadras

    Ruta: Terminal Norte (A) → Avenida Central (B) → Hospital General (G).

    Minimiza el conteo de esquinas (solo 2 saltos), pero cae en el embotellamiento (18 + 16 = 34 min).

    Implementación formal

    Implementación en Java: BFS vs. Dijkstra.

    El grafo se modela con una lista de adyacencia (Map<String, List<Arista>>), usando Queue (LinkedList) para BFS y PriorityQueue para Dijkstra:

    import java.util.*;

record Arista(String destino, int minutos) {}
record Estado(String nodo, int tiempoAcumulado) {}

public class MinutosNoCuadras {

    // 1. BFS: Minimiza cantidad de cuadras (usa Cola FIFO, ignora los minutos)
    public static Map<String, String> bfsCuadras(Map<String, List<Arista>> grafo, String origen, String meta) {
        Queue<String> cola = new LinkedList<>();
        Map<String, Integer> cuadras = new HashMap<>();
        Map<String, String> previo = new HashMap<>();

        cola.offer(origen);
        cuadras.put(origen, 0);
        previo.put(origen, null);

        while (!cola.isEmpty()) {
            String u = cola.poll(); // Saca el frente de la cola
            if (u.equals(meta)) break;

            for (Arista a : grafo.get(u)) {
                if (!cuadras.containsKey(a.destino())) {
                    cuadras.put(a.destino(), cuadras.get(u) + 1); // Cada arista suma 1 cuadra
                    previo.put(a.destino(), u);
                    cola.offer(a.destino());
                }
            }
        }
        return previo; // Ruta resultante: A -> B -> G (2 cuadras, 34 minutos)
    }

    // 2. Dijkstra: Minimiza el tiempo total en minutos (usa Cola de Prioridad)
    public static Map<String, String> dijkstraMinutos(Map<String, List<Arista>> grafo, String origen, String meta) {
        PriorityQueue<Estado> pendientes = new PriorityQueue<>(Comparator.comparingInt(Estado::tiempoAcumulado));
        Map<String, Integer> tiempo = new HashMap<>();
        Map<String, String> previo = new HashMap<>();

        tiempo.put(origen, 0);
        previo.put(origen, null);
        pendientes.offer(new Estado(origen, 0));

        while (!pendientes.isEmpty()) {
            Estado actual = pendientes.poll(); // Saca el pendiente con menor tiempo en minutos
            String u = actual.nodo();
            int d = actual.tiempoAcumulado();

            if (u.equals(meta)) break;
            if (d > tiempo.getOrDefault(u, Integer.MAX_VALUE)) continue;

            for (Arista a : grafo.get(u)) {
                int nuevoTiempo = d + a.minutos(); // Relajación de la arista en minutos
                if (nuevoTiempo < tiempo.getOrDefault(a.destino(), Integer.MAX_VALUE)) {
                    tiempo.put(a.destino(), nuevoTiempo);
                    previo.put(a.destino(), u);
                    pendientes.offer(new Estado(a.destino(), nuevoTiempo));
                }
            }
        }
        return previo; // Ruta óptima: A -> C -> D -> E -> G (14 minutos, 4 cuadras)
    }
}

    Conclusiones del taller

    ¿Qué aprendemos del Problema 4.9?

    Un resumen para responder con solidez técnica en el video explicativo:

    Porque BFS asume que todas las aristas tienen exactamente el mismo costo (1). Solo optimiza la cantidad de pasos o esquinas transitadas, resultando completamente ineficaz cuando las aristas representan tiempos variables o tráfico desigual.

    Porque Dijkstra expande una onda radial basada estrictamente en la menor distancia acumulada desde el origen, sin "mirar hacia adelante" ni predecir dónde está el destino. Nodos como C y D se confirman porque están muy cercanos en minutos a la salida, permitiendo alcanzar a E y finalmente a G con menor tiempo que la vía directa colapsada.

    En un mapa vial con tiempos de recorrido, un peso negativo carecería de sentido físico, pues implicaría retroceder en el tiempo. Dijkstra requiere estrictamente pesos no negativos (≥ 0) para asegurar que una vez un nodo es confirmado, su costo mínimo jamás podrá reducirse por caminos posteriores.

    La ruta óptima de menor tiempo es A → C → D → E → G con un total de 14 minutos (4 cuadras). La ruta BFS de menos cuadras es A → B → G con 2 cuadras, pero un tiempo de 34 minutos (20 minutos más lenta). ¡El rodeo ahorra más de la mitad del tiempo!
